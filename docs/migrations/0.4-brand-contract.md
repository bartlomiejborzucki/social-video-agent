# Migration to 0.4 executable branding

Existing EDLs and workspaces remain readable. Named built-in brand profiles
`default`, `bold-caption`, and `minimal` still render.

Project configuration written before 0.4 remains discovery context: `context
inspect` reads it as it is, and never requires migration. Making it an
**executable contract** is a different step, because from 0.4 the same file
compiles into `brand-contract.json` and drives the renderer, so every value has
to mean exactly one thing.

## What migrates by itself

These are carried over silently, because the value keeps its meaning:

- `logo` → `logo_file`, `preferred_output_directory` → `delivery_output`;
- a missing `schema_version`, which becomes `1`;
- YAML scalar shapes of an otherwise valid value: `default_fps_policy: 30`
  becomes `"30"`, `music_policy: NONE` becomes `none`.

## What you have to decide

Everything else stops with an error naming the field, the old value, and what
to write instead. Nothing is guessed, because each of these changes how the
edit looks or sounds, and a plausible-looking default would quietly overrule an
editorial decision. Ask for the full list at any time:

```bash
social-video-agent config migrate PROJECT
```

| Old value | Why it cannot be converted | What to write |
| --- | --- | --- |
| `punch_in_intensity: restrained` | the contract renders an amount, and no number is *the* meaning of the word | a number from `0` (static) to `1`; the template uses `0.25` |
| `broll_density: low` | same | a number from `0` to `1`; the template uses `0` |
| `caption_style.outline_or_shadow: subtle` | the word described strength, not which edge is drawn | `none`, `outline` or `shadow` |
| `music_policy`, `sfx_policy` as prose | the contract records permission, not a sourcing rule | `none`, `optional` or `required`, with the prose kept in the brandbook |
| `default_fps_policy: match source` | the contract must name one output rate | `30`, `60`, `30000/1001` or `60000/1001`; read the source with `social-video-agent inspect SOURCE` |
| `safe_margins`/`bottom_margin_pct` below `1` | margins were fractions and are now percentages, so `0.15` now renders as `0.15%`, not `15%` | the same margin in percent, e.g. `15` |
| `font: assets/fonts/Inter-Regular.ttf` | `font` is now the family name the renderer asks for | `font: Inter` plus `font_file: assets/fonts/Inter-Regular.ttf` |
| `logo` **and** `logo_file` both set | dropping one of two different values is the silent behaviour this refuses | delete `logo` |
| any unrecognised key | an unknown key is never ignored | remove it, or use the suggested field name |

`image_generation_policy` and `target_platforms` are 0.5 fields. They are
optional; both discovery and the contract understand them.

## Full sequence

1. run `social-video-agent config migrate PROJECT` and edit each reported field;
2. run `social-video-agent config validate PROJECT --workspace WORKSPACE`;
3. recompile Stage 2 so the EDL records the contract fingerprint;
4. rerender and run QA to create `qa/qa-brand.json`.

Old editorial fixes without `artifact` continue to target `edl`. New fixes may
target `edl`, `captions`, or `style`; all are validated as one set before files
are written.

Old unversioned delivery manifests can be read to finish an existing workspace.
New Stage 5 runs write the versioned manifest and validate every file hash.
