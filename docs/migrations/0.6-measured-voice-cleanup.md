# Migration to measured voice cleanup

Existing EDLs, cuts, captions and workspaces are untouched. This adds one
project-config key and changes what a render does to the speech.

## What is new

`audio_cleanup_policy` compiles into the brand contract:

```yaml
audio_cleanup_policy: measured   # measured | none | required
```

`measured` is the default, including for a config that does not mention the key
at all. Before this, the only thing done to the audio was loudness
normalisation to -14 LUFS with a true-peak ceiling and short fades at each cut.
Now the render also measures the cut speech and repairs what the measurement
justifies: rumble below 60 Hz, mains hum at its fundamental, an audible noise
floor, hot sibilants, and a wide loudness range. Each repair has a ceiling, and
nothing is applied without a measurement that crosses its threshold.

It is deliberately not an "enhance voice" button. A well-recorded voice comes
out untouched, and the manifest records that every check ran and every one was
below its threshold.

## What this means for an existing project

Re-run validation, then re-render:

```bash
social-video-agent config validate PROJECT --workspace WORKSPACE
social-video-agent render WORKSPACE --quality final
```

**The audio of an already-finished edit will change on its next render** if the
recording measures as needing repair. The render says so, in the output and in
`audio_cleanup_applied` in the render manifest, and names the way back. There
are two ways back, and neither touches the source:

```bash
# one render, for comparison
social-video-agent render WORKSPACE --quality final --no-audio-cleanup
```

```yaml
# permanently, for this project
audio_cleanup_policy: none
```

Source media is immutable, so the untouched audio is always one re-render away.

## What is recorded

`audio_cleanup_applied` in the render manifest holds the measurement, the
applied steps with their parameters and the reason each was applied, the
skipped steps with the reason each was not, and the ceilings in force. Brand QA
checks the policy that was used against the contract, that a measurement exists
at all, that no applied step exceeded its ceiling, and warns when the source is
clipped. The disclosure that the audio was changed is itself a QA line, so it
survives into `qa/qa-brand.json` rather than only appearing on a terminal
someone may not have been watching.

## What is not done

Clipping is reported, never repaired: reconstructing a flattened waveform is
invention, and the honest advice is to re-record with headroom. Hum harmonics
at 100 or 120 Hz are left alone because notching them thins the voice. No
filter is applied "because it usually helps", and there is no setting that
raises a ceiling — the ceilings are the design.
