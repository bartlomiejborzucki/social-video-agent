# Migration to measured caption geometry

Existing EDLs, cuts, reframe plans and workspaces are untouched. This changes
how captions are sized and laid out, and it changes two defaults.

## What was wrong

`CaptionStyle` had `font_size_pct` and `max_chars_per_cue`, but the project
config had no way to set either. A project config therefore compiled to the
renderer defaults of 5% of frame height and 32 characters per cue. At
1080x1920 that is a 96-pixel caption, which is wider than the frame for an
ordinary phrase, and the Remotion compositor resolved the overflow with
`-webkit-line-clamp` plus `overflow: hidden`: it hid the end of the line and
appended an ellipsis. `nikomu, udowadniając na siłę` rendered as
`nikomu, udowadniając na...`. A subtitle is a transcript, so that is a
correctness bug rather than a layout preference.

## What to do

Re-run validation. Nothing in the config file has to change:

```bash
social-video-agent config validate PROJECT --workspace WORKSPACE
```

Any caption key the config omits now compiles to the 9:16 reference value:

| Key | Was | Now |
| --- | --- | --- |
| `font_size_pct` | not settable (5.0) | `3.6` |
| `max_chars_per_cue` | not settable (32) | `24` |
| `max_words_per_cue` | `4` | `4` |
| `outline_or_shadow` | `outline` | `none` |
| `corner_radius` | `0` | `24` |
| `bottom_margin_pct` | `12` | `22` |

A key the config sets explicitly is still respected, so a project that wants
its outline keeps it. Because the file itself does not change, its SHA-256 does
not change either: an existing `edl.json` still matches the contract and Stage 2
does not have to be recompiled.

**Rebuild the caption track.** Cue length is part of the contract, and a track
chunked at 32 characters contains cues that this contract would have split.
Brand QA reports those as `caption cue length within the contract`. Rebuilding
captions re-chunks the same transcript against the same timeline; it does not
touch the EDL, the cuts or the reframe plan.

## New behaviour worth knowing

`config validate` now refuses a caption geometry whose own text cannot be
drawn — for example `font_size_pct: 8` with `max_chars_per_cue: 40` at
1080x1920. The message says what to lower.

At render time the Remotion route measures each cue against the project font
and hands the compositor explicit lines. When a cue does not fit: it is wrapped
at word boundaries, then that cue's font is shrunk to at most 72% of the
contracted size, then the render fails with the cue and its text named. Nothing
is truncated, hyphenated or ellipsized at any point.

`render-manifest` gains `caption_layout`: the measured box width, the widest
line drawn, the requested and smallest font sizes, which cues were shrunk,
which lost text, which gained an ellipsis, and whether the font was measured
rather than estimated. Brand QA checks all of it, plus `font_size_pct`,
`outline_or_shadow`, `corner_radius`, `max_words_per_cue` and
`max_chars_per_cue` against the contract.

A caption rendered at the old 5% is not clipped any more; it shrinks instead,
and brand QA warns that cues were reduced from the contracted size. Lower
`font_size_pct` or `max_chars_per_cue` to make that warning go away.
