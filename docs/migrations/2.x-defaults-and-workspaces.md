# Moving a project from 2.0 to the current 2.x

Releases 2.1 to 2.6 each changed a default or what a stage reads, and none had
a note of its own. This collects them. Project configs keep loading; what
changes is what an unset key means and which workspaces can be resumed.

## Workspaces and releases

A workspace records the release it was started on in `workflow-state.json`.

- A **patch** release (2.10.0 to 2.10.1) resumes it. Before, any difference in
  the version refused the workspace and pointed at a `migrate` command that
  did not exist.
- Another **release line** (2.10 to 2.11) refuses it: start a new workspace
  with `workflow init`, or install the older release to finish the edit.
- Workspaces started on 2.2 or earlier must be recreated in any case (2.3.0).

Sources are immutable, so nothing is lost with the old workspace except time.
To keep a transcript that was corrected by hand, copy `transcripts/<id>.json`
into the new workspace before `transcribe` runs: it is used as long as it was
made from the same recording, with the same options.

## 2.1 — content first is the default

With no `opening_policy` key the project gets `content_first`: the render
refuses a timeline that opens on a title card, a cover, a still, a logo or a
Claude Motion card; Stage 5 cannot complete while the measured opening breaks
the rule; the cover is delivered as `cover.jpg`; `motion suggest` proposes no
hook card.

To keep an opening card, say so: `opening_policy: free`.

## 2.4 — the transcript file is the source of truth

`transcripts/<id>.json` is what every stage reads. The cache only fills it,
and a stage no longer transcribes over it with its own default model. To
change a transcript, run `transcribe` again (or `captions fix` for single
words) rather than deleting cache entries.

A scene title is fitted to its tab by width, down to 60 % of its size, instead
of being cut at 48 characters. A title that still does not fit is refused with
the length that would.

## 2.5 — every generated image needs a yes

`image_generation_policy` defaults to `ask`. A project that relied on the
earlier default states its policy in the config.

## 2.6 — music and sound effects are no longer gated

`audio_bed` and `sound_effects` need no `license_confirmed`, and `motion sfx`
needs no `--licensed` (still accepted). `music_policy` and `sfx_policy` remain
in the config as recorded preferences; the render and brand QA no longer
enforce them. Clearing the rights to music stays with the user.

## 2.11 — delivered videos are named `NAME-FINAL`

`final.mp4` in a delivery folder is now `NAME-FINAL.mp4`, and every variant
follows it: `NAME-FINAL-no-captions.mp4`, `NAME-FINAL-en.mp4`,
`NAME-FINAL-1080x1350.mp4`, `NAME-FINAL-hook-<name>.mp4`. `NAME` is `deliver
--name`, else the edit's name, else the first recording's id. Anything that
picked the files up by their old names should read the paths from
`delivery-manifest.json`. The workspace's `final/final.mp4` is unchanged.

An edit with a music bed gets a second video, `NAME-FINAL-no-music.mp4`, and
so takes about twice as long to deliver; `--one-audio` keeps the old
behaviour.

## 2.12 — the picture is corrected by default

`picture_policy` defaults to `measured`: a recording that measures dark is
lifted, one the edit enlarges is sharpened, one that is heavily compressed is
lightly denoised. A good recording is unchanged, so most projects see no
difference; one with an evening or a messenger recording will. The render
prints what it changed. To keep the picture exactly as recorded:

```yaml
picture_policy: none
```

or `render --no-picture-correction` for one render. A final rendered before
2.12 has no correction recorded, and delivery keeps its variants the same.

Loudness: where a mix needed more gain than its peaks allowed, the level used
to be ridden over time. It now gets one gain and a limiter, and recordings in
one edit are moved to one speech level. A re-render of an older edit can
therefore sound steadier and start quieter than before; `audio_cleanup_policy:
none` keeps each recording's own level.

`compile` no longer cuts between passages of one recording closer than
0.25 s. An edit plan that split a take into beats to create jumps now gets
them only where the framing (`zoom`) changes; set `min_cut_gap: 0` in the
output profile for the old behaviour.

## 2.13 — zooms push in on the face

A range with `zoom` and a measured face is framed differently: the push-in
goes toward the speaker's eyes and keeps them where they were, instead of
toward the middle of the frame. A reframe plan made before 2.13 has no
measured focus, so an existing `edl.json` renders as it did; a recompile (or
running the reframe stage again) measures it.

A face crop that has room vertically now puts the eyes at 30 % of the frame
height. Top-zone cards may be drawn up to 30 % smaller where they would cover
the forehead. Neither has a switch; an EDL's recorded `reframe` can be edited
by hand as before.

## 2.11 — a renderer without libass refuses captions

An ffmpeg built without libass used to render without the captions and record
the video as captioned. It now stops with the fix: `social-video-agent doctor
--install-ffmpeg`, or an ffmpeg built with libass.
